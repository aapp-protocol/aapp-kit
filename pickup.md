## 🆕 New Ideas / Prompt Inputs
- [ ] Verbosity Budget: keep agents to the essence everywhere. (1) Caps stay on public records (subject, changelog, issue text via #111). (2) Detail goes behind a pointer (`see P-38 §2.3`, `#109`), never restated. (3) Longer context goes to git notes (`aapp note`). (4) Pre-commit warning, not refusal, for added code comments: comment blocks longer than a few lines, a high comment-to-code ratio in short functions, history wording ("previously", "used to", "renamed from") and plan/issue tags (`(P-54)`, `(#103)`).
- [ ] Configuration Profiles & Test-Gate Recipe (for P-56's cookbook): an advisory recipe (e.g. `docs/recipes/getting-started/configuration-profiles.md`) with copy-paste `git config` blocks and a one-line reason per key for four intended uses: solo human-led; one agent, one checkout; several agents in parallel (plan worktrees, `integrate`, strict attribution, quarantine); team with pull requests (`integrate hook`). `aapp.planSession` stays personal, outside every profile. Plus a recipe for registering P-60's `pre-done` test gate (hash, registry line, timeout). Docs only; fold into P-56.
- [ ] Configuration Manager CLI (`aapp config`): Add manifest-backed `config.tsv` and `aapp config` command (`list`, `get`, `set`) with type validation to inspect and manage `git config aapp.*` repository settings.
- [ ] Work Dispatch Queue for Multi-Agent Execution: (`aapp dispatch` / `aapp queue`) In multi-agent environments implementing multiple plans concurrently across isolated worktrees, a central work dispatch queue would coordinate which agent claims which plan. Currently, `state_matrix.md` defines the human priority sequence, but there is no automated worker claiming/leasing mechanism (`aapp next` / `aapp claim`) or queue tracker to allocate frozen, unblocked plans to idle agents without collisions or duplicate effort. Explore introducing a lightweight queue/workpool protocol. Also covers integration: merge finished plans into `develop` one at a time, keeping both sides of `CHANGELOG.md` conflicts, stopping only on real code conflicts (from the P-48 rework). *Not carried in P-54: automatic worktree removal (with safeguards for untracked/ignored files), worker claiming/leasing, and sequential branch integration. Those stay with this Work Dispatch Queue pickup idea (RFC P-52/P-54).*
- [ ] Autonomous Blast-Radius Lease Negotiation & Quarantined Handoff: When an autonomous or unattended agent hits an out-of-bounds file collision caused by an intentional clean break (e.g. legacy test suites breaking on new fail-closed invariants), unattended execution cannot prompt a human. Explore a structured negotiation protocol: (1) requesting a signed out-of-band blast-radius lease expansion from an evaluator/orchestrator, or (2) executing a Quarantined Partial Handoff (committing in-bounds changes proven green under unit isolation, reverting the out-of-bounds collateral file, and emitting an automated regression handoff ticket). Long-range capability for autonomous agent fleets.
- [ ] Reserved ID Blocks: provider plugin pre-reserves plan/issue IDs so allocation works while it is unreachable. Design: P-32 Q5.
- [ ] Layer-0 Enforcement Practice & Unsupervised Agent Security Manual: (docs only, not kit code) the kit's guards keep cooperating humans and agents on protocol; they do not stop a determined or unconstrained actor with raw shell access (e.g. any agent running arbitrary bash could edit files without sudo checks or send a started/blocked plan back to Refining by hand, #104). Author a comprehensive high-assurance deployment manual for unsupervised agents running on servers and security-critical enterprise environments: (1) externalized tool boundaries: the `aapp` binary and runtime engine live strictly outside the repo (`/usr/local/bin/aapp` and `~/.local/share/aapp-kit/`), completely out of reach of agent workspace tools; (2) OS-level permission hardening: separate OS users and file ownership (`chown root:root` / `chmod 644` or `chmod 755`) for `.githooks/`, `.git/hooks/`, and `.agents/skills/aapp-hooks/registry.tsv`, ensuring that even raw shell scripts fail at the kernel VFS level with `EACCES (Permission denied)` if attempting to alter pinned hook SHAs without `sudo`; (3) container isolation: mounting governance directories and hooks as read-only volumes (`:ro`) in containerized agent runners (Docker/K8s); (4) architectural role separation: planning in one isolated worktree/machine and developing in another with separate agents; a read-only plans worktree for coding agents, with issue reporting delegated through audited hooks; (5) server-side branch protections and push-validation gates on the `plans` and `develop` branches. The kit must keep functioning seamlessly under these restrictive OS permissions; verify this compatibility and document the full 5-tier defense-in-depth trust model.
- [ ] Test Time & Kit Modularity (research, likely a programme of plans): the `pre-done` test gate runs the full suite (~6 min) on every `done`. Scoping tests to a plan's changed files is unsafe while modules share state and helpers (sourced globals such as `REPO_ROOT`, `PLANS_DIR`, `PRIMARY_ROOT`; one helper used by many verbs): a changed export breaks callers outside the diff (#114: P-61 broke 22 tests outside its files). Research: map cross-module coupling, reduce it into modules with declared interfaces, then decide test tiers: scoped on `done`, full at group merge into `develop` and at release (`/aapp-release`). Also a partial test interface: verbs and helper commands tested on their own, for less time, CPU and I/O. Related: worktree-contexts RFC C5 (scoped gate); parallel suites are P-67.
- [ ] Cookbook recipe "Planning a Plan Group": (`docs/recipes/workflows/planning-a-plan-group.md`, listed in P-56 Task 1.4) how related plans are grown and kept aligned, with group P-72 as the worked example: start from one plan, add a member when a gap shows, carry each decision to every plan at once, what goes in the group plan (shared decisions, order with reasons, end-state architecture), the checks that catch mistakes (conflict check, code landing meanwhile), when planning is done. Write it after P-72 ships, so it covers how the plans held during implementation.
- [ ] AI Attribution Integrity & Model Introspection Enforcement: (Bare-Word & Placeholder Refusal) In multi-agent autonomous pair programming, commits carry semantic trailers (`AI-Agent`, `AI-Vendor`, `AI-Model`) to provide contribution audit trails and accurate model benchmarking telemetry. Currently, agents exhibit headless copy-paste behavior: when documentation tables show concrete examples (`gemini-1.5-pro`, `claude-3-5-sonnet-20241022`), agents blindly parrot the example string into `aapp commit` instead of querying their active runtime model. (1) De-bias documentation: update `AGENTS.md` and templates to use explicit parameter placeholders (`agent <Agent> vendor <Vendor> model <ActualModel>`) and remove misleading static model names. (2) Mechanical refusal gate: `aapp commit` and `aapp-commit-msg` validate attribution when enabled (`strict`, or `lax` when trailers are present), rejecting empty values, bracketed placeholders (`<ActualModel>`, `<Model ID>`), bare placeholder tokens (`ActualModel`, `ModelID`, `unknown`, `Model`), and unverified template copy-pastes (`gemini-1.5-pro`). (3) Actionable error loop: a refusal outputs an explicit prompt requiring the agent to identify its actual active model from its session context, forcing autonomous agents to self-correct on retry rather than committing corrupted metadata.
- [ ] Web Orchestration, CLI Telemetry & Zero-File Prompt Protocol: Design for external companion web app (`aapp-web`) managing autonomous agents, receiving structured CLI execution logs (`exec.jsonl`), integrating directly with a JSON-native CMS via typed JSON Block Kit, and implementing a zero-file IPC bridge (Unix socket / HTTP) for real-time and asynchronous human-in-the-loop decisions. Full transcript, questions and schemas in `.plans/pickup/web-orchestration-and-prompt-protocol-rfc.md`.
- [ ] Perl in place of python3: the kit is bash; python3 is only its JSON helper, and Perl would take that role. Uses to port: `templates/blast-radius-guard.sh` (tool payload parsing, the deny answer, the pause reason; keep its grep/sed fallback), `templates/aapp-pre-commit` (the pause reason), `lib/cmd_pause.sh` (the pause snapshot, written and read, 3 places), `lib/cmd_status.sh` (the pause banner), `lib/cmd_init.sh` (`merge_blast_radius_guard`, the `.claude/settings.json` merge), tests (`tests/write-guard_test.sh` payloads, `tests/verbs/plan.sh` JSON check, `tests/output_json_test.sh` from P-94). Targets are the templates, never the installed copies in `.githooks/`. The adopter language checks in the pre-commit go, not ported (#159), so no Python is left. `JSON::PP` is core Perl but packaged apart on Fedora/RHEL and missing from Debian's `perl-base`: a fallback stays needed.
- [ ] Off-machine copy of group work: a group's feature branch and the `plans` branch exist only on the developer's machine until pushed; a disk failure or an unclean shutdown can cost a whole group. Push both to the remote after each member's `done` (and the amendments member's `land`): a `post-done` hook does it today; a kit setting would make it the default. Durability on the machine itself is `git config core.fsync committed` (an adoption advisory candidate).
